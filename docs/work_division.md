# RK3588 NPU 项目分工详细文档

## 概述

现在需要将当前单次token推理的worker扩展为完整的对话系统。采用两人分工：**第一个人负责高层对话实现**，**第二个人负责底层性能优化**。两人通过`LLMEngine` API接口协作，避免代码重合。

分工原则：
- **第一个人**：专注API层及以上，实现对话管理、调度、用户接口。
- **第二个人**：专注模型层及以下，实现算子优化、流水线、KV cache优化。
- **接口约定**：所有交互通过`LLMEngine`及其扩展接口进行。

## 第一个人：高层对话实现

### 目标
将项目从单次推理扩展为真正的LLM对话系统，支持多轮对话、并发请求、流式输出等功能。类似vLLM的调度器，但基于现有C++代码自实现。

### 具体任务

#### 1. 对话状态管理
- **多轮对话支持**：维护对话历史，自动拼接上下文。
- **会话隔离**：每个用户/请求独立KV cache，支持并发会话。
- **上下文管理**：智能截断过长历史，保留最近消息。
- **实现文件**：新建 `include/api/session_manager.h`, `src/api/session_manager.cpp`

#### 2. 请求调度和批处理
- **并发请求队列**：实现请求队列，支持多个用户同时请求。
- **动态批处理**：根据硬件负载调整批大小，优化吞吐量。
- **优先级调度**：支持紧急请求优先处理。
- **实现文件**：新建 `include/api/request_scheduler.h`, `src/api/request_scheduler.cpp`

#### 3. 采样策略扩展
- **多种采样**：实现top-k、top-p、temperature等策略。
- **停止条件**：自定义停止token、最大长度、时间限制。
- **实现文件**：扩展 `include/api/generation_config.h`, `src/api/llm_engine.cpp`

#### 4. 流式输出和API封装
- **流式生成**：实时输出token，支持中断/取消。
- **类似PyTorch接口**：提供 `generate()` 支持文本输入/输出。
- **可选REST API**：实现HTTP服务，支持远程调用。
- **实现文件**：扩展 `include/api/llm_engine.h`, 新建 `include/api/chat_interface.h`

#### 5. 测试和集成
- **对话测试用例**：验证多轮对话正确性。
- **性能监控**：统计延迟、吞吐量、内存使用。
- **与现有脚本集成**：扩展 `scripts/chat.py` 为多用户服务器。

### 工作量评估
- 难点：并发编程、状态管理、用户体验优化
- 依赖：第二个人提供的优化接口

## 第二个人：底层性能优化

### 目标
优化当前CPU/NPU分工不平衡的问题，提升推理速度和效率。当前矩阵乘在NPU，其他算子在CPU，需通过流水线和算子转换实现并行，kv cache。

### 具体任务

#### 1. 算子优化和转换
- **CPU算子矩阵化**：将RMSNorm、RoPE、Softmax等转换为可能的矩阵操作，利用NPU。
- **SIMD/NEON优化**：对剩余CPU算子使用向量化指令。
- **算子融合**：合并多个小算子为单个NPU调用。
- **实现文件**：修改 `src/ops/`, `include/ops/`

#### 2. 流水线并行
- **CPU-NPU流水线**：预处理与计算并行执行。
- **多核利用**：分配任务到RK3588的6个CPU核。
- **异步执行**：使用线程池实现非阻塞推理。
- **实现文件**：新建 `include/core/thread_pool.h`, 修改 `src/api/llm_engine.cpp`

#### 3. KV Cache优化
- **Paged KV Cache**：动态分配内存，支持长序列。
- **KV量化**：FP16→INT8压缩，减少内存带宽。
- **Flash Attention优化**：优化注意力计算。
- **实现文件**：修改 `include/model/kv_cache.h`, `src/model/kv_cache.cpp`

#### 4. 后端扩展
- **多NPU核心**：利用RK3588的3个NPU核心并行。
- **内存优化**：权重预加载、内存池管理。
- **性能剖析**：添加计时器，识别瓶颈。
- **实现文件**：修改 `include/backend/npu_linear.h`, `src/backend/npu_linear.cpp`

#### 5. 性能测试
- **基准测试**：对比优化前后的速度/内存。
- **正确性验证**：确保优化不影响精度。
- **实现文件**：扩展 `src/main.cpp` 添加测试模式。

### 工作量评估
- 总计：10-13周
- 难点：硬件优化、并行编程、内存管理
- 依赖：第一个人提供的性能需求
