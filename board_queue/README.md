# `rkq` 使用

这是一个给 RK3588 单板共享场景准备的轻量任务排队工具。

解决的问题：

- 多个人共用一块板子
- 跑的程序可能完全不同
- 会争抢同一套 NPU / CPU 资源
- 如果同时运行，测速、吞吐、延迟结果就没有参考价值

做的事情很简单：

- 所有任务先排队
- 同一时刻只允许一个任务真正开始运行
- 其他任务等待
- 当前任务结束后，下一个任务自动开始

## 1. 设计思路

`rkq` 采用“命令前缀”的使用方式，不要求大家统一项目结构，也不要求你提前知道每条路线的启动方式。

只要把原本要运行的命令前面加一个：

```bash
rkq run -- <原命令>
```

就可以让这个命令进入队列管理，但是注意原命令第一个参数也就是可执行文件路径最好以 `./` 活 `/` 开头

例如：

```bash
rkq run -- ./worker_rpc_server Qwen1.5B 0.0.0.0:5001
rkq run -- ./qwen2_demo Qwen1.5B 151644 8948 198 ...
rkq run -- ./main -m ./models/model.gguf -p "hello" -n 64
rkq run -- ./python serve.py --model /root/model
```

## 2. 基本命令

当前支持的命令如下：

```bash
rkq run -- <command...>
rkq status
rkq current
rkq cancel <task_id>
```

### 2.1 `rkq run -- <command...>`

作用：

- 提交一个任务到等待队列
- 如果当前没有其他任务运行，则立即开始
- 如果当前已有任务运行，则进入等待
- 轮到你时自动执行原命令

注意：

如果此时有人在占用，会输出提示等待信息，这时终端还处于阻塞状态，按ctrl+c不会取消任务(所以这是暂时先不要ctrl+c)，只是退出rkq这个程序，这样即使任务运行了输出也会丢失，所以可以手动通过 `rkq status` 查看刚刚提交的任务然后使用 `rkq cancel <task_id>` 取消任务

示例：

```bash
rkq run -- ./worker_rpc_server Qwen1.5B 0.0.0.0:5001
rkq run -- ./qwen2_demo Qwen1.5B 151644 8948 198 ...
rkq run -- ./main -m ./models/model.gguf -p "hello" -n 64
```

注意事项：

- `--` 后面就是你原来要运行的命令
- 第一个可执行文件建议写成 `./程序名` 或绝对路径
- 不建议只写裸命令名，例如 `qwen2_demo`

推荐写法：

```bash
rkq run -- ./qwen2_demo ...
```

不推荐写法：

```bash
rkq run -- qwen2_demo ...
```

原因是当前内部使用 `execvp`，如果只写 `qwen2_demo`，会去 `PATH` 中查找，而不会默认在当前目录查找。

### 2.2 `rkq status`

作用：

- 查看当前正在运行的任务
- 查看整个等待队列

输出大致包含：

- 当前运行任务的 `task_id`
- 运行用户
- 启动时间
- 工作目录
- 原始命令
- 等待队列中的所有任务

适合用来查看：

- 现在板子上有没有人正在跑
- 你前面还有几个人
- 其他人提交的命令是什么

### 2.3 `rkq current`

作用：

- 只查看当前正在运行的那个任务

示例：

```bash
rkq current
```

如果当前没人运行，会输出：

```text
No running task.
```

### 2.4 `rkq cancel <task_id>`

作用：

- 取消一个**尚未开始运行**的排队任务

示例：

```bash
rkq cancel 1780062805582_root_21504
```

当前版本限制：

- 只能取消排队中的任务
- 不能用来强制停止已经开始运行的任务



## 3. 取消与停止

### 3.1 任务还没开始，只是在排队

这种情况下，正式取消方式是：

```bash
rkq cancel <task_id>
```

这会把等待中的任务从队列中移除。

### 3.2 任务已经开始运行

当前版本下，正在运行的任务**不能**通过 `rkq cancel` 强制停掉。

目前支持的停止方式是：

- 启动该任务的用户，在当前终端按 `Ctrl+C`

这是因为 `rkq` 已经实现了信号转发：

- 你按下 `Ctrl+C`
- `rkq` 收到 `SIGINT`
- `rkq` 把该信号转发给真正运行的子进程
- 子进程退出后，队列状态会释放

所以当前推荐约定是：

- 排队中不想等了：用 `rkq cancel <task_id>`
- 已经开始运行，想自己停掉：在运行终端按 `Ctrl+C`

### 3.3 等待阶段按 `Ctrl+C` 会怎样

当前版本下，如果任务还在等待，而你直接在等待界面按 `Ctrl+C`：

- 会中断当前这个 `rkq` 进程
- 同时它会尝试把这次等待中的任务从队列中清掉

但严格来说，组内仍建议使用正式取消方式：

```bash
rkq cancel <task_id>
```

因为这个语义更明确。




## 4. 当前能力范围

`rkq` 目前解决的是“任务级串行排队”问题。

已支持：

- 任务提交
- 等待队列
- 当前任务查看
- 取消尚未开始的任务
- 记录当前运行状态和历史日志

当前**不包含**：

- 批处理
- 推理框架内部请求合并
- 真正常驻后台服务
- 强制阻止别人绕过 `rkq` 直接运行程序

换句话说，`rkq` 是一个“约定式”的共享资源管理器：

- 大家都通过 `rkq run -- ...` 提交任务，排队机制就成立
- 如果有人绕过 `rkq` 直接运行程序，仍然可能发生资源竞争

## 5. 构建方式

### 5.1 本机测试构建

如果你只想在当前机器上本地测试逻辑：

```bash
cd board_queue
mkdir -p build && cd build
cmake ..
cmake --build . -j4
```

生成的本机可执行文件：

```bash
./rkq
```

注意：
- 在 WSL / Linux PC 上本地编出来的一般是 `x86-64`
- 这种版本**不能直接传到 RK3588 板子上运行**

### 5.2 给 RK3588 板子使用的交叉编译

如果需要生成给板子用的版本，请在 WSL 上使用交叉编译脚本：

```bash
cd board_queue
chmod +x build-linux.sh
./build-linux.sh
```

如果环境变量没有配置，可先执行：

```bash
export GCC_COMPILER=aarch64-linux-gnu
```

交叉编译后的产物位于：

```bash
install/rkq
```

建议用 `file` 检查架构：

```bash
file install/rkq
```

正确的板子版本应类似：

```text
ELF 64-bit LSB pie executable, ARM aarch64, ...
```

如果看到的是：

```text
x86-64
```

说明这个文件不能在板子上运行。

## 6. 板子上安装为全局命令

为了方便组内成员使用，建议把 `rkq` 安装为全局命令。

例如，把交叉编译后的板子版 `rkq` 放到板子上后，执行：

```bash
cp /root/npu-manager/rkq /usr/local/bin/rkq
chmod +x /usr/local/bin/rkq
```

然后测试：

```bash
which rkq
rkq status
```

## 7. 输出行为

`rkq` 的设计目标之一是尽量保持你原来运行程序的体验不变。

当你执行：

```bash
rkq run -- ./worker_rpc_server Qwen1.5B 0.0.0.0:5001
```

你会先看到 `rkq` 自己的一些提示，例如：

- 已入队
- 当前排第几
- 轮到你开始运行了
- 结束时退出码是多少

而一旦真正开始执行原命令后：

- 原程序的标准输出仍然直接打印到当前终端
- 原程序的标准错误也仍然直接打印到当前终端
- token 输出、报错信息、日志显示方式都和直接运行原命令时基本一致

因此，从用户体验上看：

- 等待阶段由 `rkq` 管理
- 运行阶段基本就是“像原来一样”

## 8. 整体工作逻辑

`rkq` 当前不是常驻后台进程，而是一个前台命令包装器。

当你执行：

```bash
rkq run -- <你的命令>
```

内部大致会发生这些步骤：

1. 生成一个唯一的 `task_id`
2. 记录：
   - 用户名
   - 提交时间
   - 当前目录
   - 原始命令
   - 提交进程 PID
3. 将任务写入队列目录
4. 循环判断：
   - 自己是否排在队首
   - 当前是否有其他任务正在运行
5. 如果轮到自己，则：
   - 把自己写为“当前运行任务”
   - `fork + exec` 启动原命令
6. 原命令结束后：
   - 记录退出状态
   - 清理当前运行标记
   - 允许下一个任务开始

## 9. 状态目录

默认状态目录为：

```bash
/tmp/rkq
```

目录内主要文件如下：

- `queue/`
  - 等待中的任务文件
- `finished/`
  - 已结束任务的快照
- `current.task`
  - 当前正在运行的任务
- `history.log`
  - 历史事件日志
- `state.lock`
  - 用于串行化队列状态修改的锁文件
